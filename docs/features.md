# Feature scaffolding (detail)

## Feature Scaffolding

- `src/features/movies/` — `mock.tsx` (`ALL_MOVIES` — the desktop preview popover's field fallback, since the list endpoint returns a shallow movie), `constants.ts` (FALLBACK_GENRES, FALLBACK_AGE_RATINGS, FALLBACK_FORMATS, RELEASE_OPTIONS, LENGTH_OPTIONS, RATING_MIN/RATING_MAX/RATING_STEP, MOVIES_PAGE_SIZE, DEFAULT_FILTERS), `types.ts` (Movie/CastMember/FeaturedMovie re-exports + Tab, Filters, MovieQuery, MoviesMeta, CatalogOption, FilterOptions), `url.ts` (searchParams ⇄ state), `api.ts` (`buildMovieQuery`, `getMovies`, `getFeaturedMovies`, `getMovieDetail`, `getGenres`/`getFormats`/`getAgeRatings` — all LIVE), `moviePreviewContext.tsx` (`MoviePreviewProvider` + `useMoviePreview` — the hover preview shared by the home desktop rows: 200 ms dwell, per-locale detail cache, a slow answer for a movie the cursor already left is dropped) and `components/MoviePreviewPopover.tsx` (the cursor-following card it portals; the only consumer of `mock.tsx`). The list itself has no hooks — `page.tsx` calls API directly via `await`.
- `src/features/showtimes/` — `types.ts` (`ShowtimeSlot`, `GroupedShowtimeCinema`, `ShowtimesResponse`, `ShowtimeDateOption`, `ShowtimeDetail`), `api.ts` (`getShowtimes`, `getShowtimeDates`, `getShowtimeById`), `utils.ts` (`toShowtimeDateChips` + the exported `ShowtimeDateChip` its callers paint, `isValidDateParam`, `buildFallbackDateChips`), `context.tsx` (`ShowtimesProvider` — the movie-detail date/slot strip), `hooks/useQuickBooking.ts` (home quick-booking controller: dates → cinemas → slots; every list is stored with the request key it answers, so a slow response can never overwrite a newer one), `components/{CinemaCard,DatePicker}.tsx` (the slot/date pickers shared by the booking and modify flows).
- `src/features/tickets/` — `constants.ts` (TICKET_STATUS), `types.ts` (FoodDrinkItem, UpcomingTicket, PastTicket, Recipient, TicketTransfer, SeatTicket, ModificationType, ModificationSeat, EligibleShowtime), `status.ts` (`PAST_STATUS_META` — past-ticket `status` → `{ labelKey }`, the single source for the listing badge + `isPastStatus()` narrowing guard; the FE-only `transferred` status covers a ticket given away), `api.ts` (LIVE: getUpcomingTickets, getPastTickets, getTicketById — also pulls `GET /payment-methods` in parallel so the receipt can name the method, getEligibleShowtimes — takes the locale because `format` is catalog content, getRecipient — exact-email recipient lookup via `GET /user/search`), `utils.ts` (`getModifyErrorMessage`/`getCancelErrorMessage`: backend rejection `code` → `tickets.modify.error.*`/`tickets.cancel.error.*` locale key, unmapped code falls back to the server message), `action.ts` (server actions: `createTransferAction`/`cancelTransferAction`/`acceptTransferAction`/`declineTransferAction` take `(prevState, formData: FormData)` and forward the refresh cookie; `modifyTicketAction`/`cancelTicketAction` take `(prevState, { …, token })` — `"use server"`; every failure union may carry `status`/`code`), `adapters.ts` (wire → UI mapping + `TicketPageMeta` + recipient/eligible-showtime adapters), `contexts/` (TransferContext, TicketDetailContext, ModificationContext — no listing context), `hooks/` (`useTransferSubmit` confirm-form binding, `useTransferDecisions` accept/decline, `useCancelTransfer`, `useCancelFlow` the 4-view cancel machine — a refusal shows the localized reason, not a refund amount, `useModifySubmit` review-step submit — sends only the fields that changed and renders the localized rejection; there is no modify payment step because the backend accepts same-price changes only), `components/` (`TicketRealtimeRefresh`, `TransferConfirmForm`, `TicketOverviewCard` — the identity card every ticket surface reads, `EligibleShowtimesAdopter`/`ShowtimeStepBody`/`ModifySeatMapAdopter`/`SeatMapStepBody` — effect-only fetch owners + render gates shared by the modify wizard's both device trees). No mock file.
- `src/features/notifications/` — `mock.tsx`, `constants.ts` (`NOTIFICATION_EVENT` + `TICKET_UPDATED_EVENT` window event), `types.ts` (`Notification` + `NotificationMeta`), `api.ts` (`getNotifications(cookie?, locale)` — `withLang`'d, since the backend renders each notice from a stored code + params), `adapters.ts` (`toNotification` narrows the free-form `meta` JSON to `{ ticketId? }`), `context.tsx` (the provider keys its socket effect on `locale` too: a locale switch re-reads the inbox in the new language, and a push is re-read before it is announced so the toast is localized), `components/NotificationRow.tsx` (the inbox row shared by the header popup and the desktop page — see _Notifications_).
- `src/features/auth/` — `types.ts` (User, LoginRequest, LoginResponse, RegisterRequest, RegisterResponse, RefreshResponse), `action.ts` (server actions: loginAction, registerAction, refreshAction, logoutAction — `"use server"`), `schema.ts` (createLoginSchema, createRegisterSchema — Zod factory functions with i18n).
- `src/features/profile/` — `types.ts` (User interface, UpdateProfileRequest), `action.ts` (updateProfileAction server action).
- `src/features/reviews/` — `mock.ts` (FILTERS with FilterKey), `types.ts` (FilterKey, `MovieReview` + `MyReview`/`MyReviewsResponse` for `/reviews/me`, `UiReview` — the mapped row the detail cards render), `api.ts` (`getReviewFilters`, `getReviews`, `getMyReviews`, client-interactive `deleteMyReview`), `action.ts` (movie-detail review server actions), `hooks/` (`useMovieReviews` detail-page paging/mutations + `formatReviewCount`, `useReviewHighlight` the shared `#review-<id>` deep-link: scroll + 4 s ring + bounded page hunt, `useReviewComposer` the WriteReview draft, `useReviewEditor` one card's inline edit state — both clip the body to `REVIEW_MAX_LENGTH` so an over-typed review can never be submitted), `components/{mobile,desktop}/{WriteReview,ReviewCard}.tsx` (presentation only — both skins drive the same two hooks; the desktop composer keeps the counter and cap the mobile one always had), `constants.ts` (`REVIEWS_PAGE_SIZE`, `REVIEW_MAX_LENGTH = 500`).
- `src/features/wishlist/` — no mock (deleted): `types.ts` (`WishlistItem`, `WishlistMovie` — exact BE payload, `WishlistTab`), `api.ts` (LIVE: `getWishlist` + client-interactive `addWishlist`/`removeWishlist` with RAM Bearer, seat-holds precedent), `context.tsx` (WishlistProvider, useWishlist — `toggleWishlist(id, feedback?)` is the single choke point for every heart: optimistic local + BE sync when logged in with rollback + toast; logged-out picks mirror to `localStorage("wishlist")` with mount restore).
- `src/features/booking/` — `types.ts` (the booking domain types — `Showtime`, `Cinema`, `DateOption`, `SeatKind`/`SeatStatus`/`Seat`/`SeatRow`/`SeatPrice`, `FoodCategory`/`ComboItem`/`FoodItem` — plus SelectedSeat/SelectedCombo/SelectedFood/BookingMovie/BOOKING_STEP_KEYS and the wire types: SeatMapCell/SeatMapRow/SeatMapResponse/CurrentSeatHoldResponse/SeatHoldResponse/PaymentMethodId (opaque string — only the catalog names a method)/PaymentMethodOption/PaymentCatalog/BookingStatus/PaymentFailReason/BookingDetail/PaymentIntent(+Status/Kind)/PaymentSettlement/PaymentOutcome(+WithIntent)/SimulatedOutcome), `utils/` domain folder: `seat.ts` (`getSeatLabel` — the single seat-label format everywhere; grid helpers `restoreSelectedSeats`/`selectCellsByIds`/`clearGridSelection`), `cinema.ts` (`findShowtime`/`resolveSlotSelection`/`resolveCinemaAdoption` — step selection + URL adoption), `bookingCard.ts` (`bookingCardData(booking, paymentMethods)` — BookingDetail → card props: merged sweetbox seats, snacks, payment-method label resolved from the catalog, theater/date/bookingRef), `snack.ts` (`withItemQty` stepper upsert), `seatMap.ts` (`adaptSeatMap` — wire GET /seats → SeatGrid `SeatRow[]`: kind mapping, multi-segment cell splitting, price passthrough), `api.ts` (LIVE: `getSeatMap`, `getCombos`, `getFoodItems`, `getFoodCategories`, `getPaymentMethods` → `PaymentCatalog` with the envelope `meta.demo`, `getSeatHolds`/`saveSeatHolds`/`releaseSeatHolds` + `getPaymentIntent` (client-interactive, Bearer from RAM), `getBookingById`), `action.ts` (`"use server"`: `createBookingAction`, `createPaymentIntentAction`, `simulatePaymentAction`, `syncPaymentAction` — see Server Actions Convention), `paymentBrand.ts` (`getPaymentLabel(methods, id)` — the one label lookup, falling back to a humanized id when the catalog does not list it; `getPaymentBrandImage(id)` — logo path or `null`, presentation only), `constants.ts` (`BOOKING_SESSION_SECONDS` = 600 — session clock seed), `context.tsx` (BookingProvider, useBooking — thin dispatch wrappers over the reducer), `reducer.ts` (BookingState, BookingAction, bookingReducer, INITIAL_BOOKING_STATE — the seat grid and cinema-step UI state live here too), `hooks/` (`useSeatHolds.ts` client seat-hold lifecycle: restore/release/early-hold safety, the session end is enforced by `SessionExpiryWatcher` not the hook; `useSeatHoldSubmit.ts` seats-step CTA; `useCinemaSelection.ts` cinema filter + slot toggle; `useContactDraft.ts` credentials fields + draft sync; `useSubmitBooking.ts` payment create → QR hand-off; `usePaymentIntent.ts` QR screen get-or-create + 3 s poll + simulate/sync + terminal routing), `components/` (`OrderSummary` — the credentials/payment recap, `ReceiptCard` — the shared order receipt (success page + QR page), `payment/{PaymentQrCard,PaymentIntentActions,PaymentStatusPanel}` — the QR page's shared blocks, `seats/{SeatGrid,SeatCell,SeatLegend}` the seat map primitives, plus the effect-only mount helpers/guards `CinemaAdopt`, `PaidBookingReset`, `PaymentDefaultAdopt`, `SeatMapAdopter`, `SessionExpiryWatcher`, `RequireDraft`). No mock file.
- `src/hooks/` — `useDevice.ts` (returns `"mobile" | "desktop"` via `matchMedia`), `useMounted.ts` (post-mount flip for staged entry animations), `useAppendReveal.ts` (grow-reveal + scroll for movies/tickets/reviews lists), `useDebouncedValue.ts` (value that settles after `delayMs`)
- `src/libs/utils.ts` has `slugify`, `formatVND`, `formatDate`, `formatRelativeTime`, `toLocaleTag` (the single `en`→`en-US`/`vn`→`vi-VN` mapping every `toLocale*` call needs), `getSafeReturnUrl`, `authReturnTarget`, `buildLoginUrl`, `buildRegisterUrl`; `src/libs/date.ts` has `formatDateOnly` (calendar dates), `CINEMA_TIMEZONE` + `todayInCinemaZone()` (the cinema's day, never the device's — chips and date params are keyed on it); `src/libs/zod.ts` has shared Zod validators (`isValidPhone`, password regex patterns) and `PASSWORD_RULES` (the checklist/schema single source); `src/types/index.ts` has shared types (`Device`, `Movie`, `CastMember`, `FeaturedMovie`). Feature-specific types live in `features/*/types.ts`. Feature-specific Zod schemas live in `features/*/schema.ts`.
