# Feature scaffolding (detail)

## Feature Scaffolding

Folder rules (R1–R7) live in `AGENTS.md` §Layering; this file is the inventory of what each domain owns.

Visual components are owned by their route under `src/app/**/components/`, or by `src/components/shared/` when multiple features reuse the presentation. Feature folders contain API calls, types, business logic, hooks, contexts and state; they do not contain visual component directories. Page loaders should compose individual API calls in async route sections; combine reads only when they are required to render one cohesive UI block.

- `src/features/movies/` — `constants.ts` (FALLBACK_GENRES, FALLBACK_AGE_RATINGS, FALLBACK_FORMATS, RELEASE_OPTIONS, LENGTH_OPTIONS, RATING_MIN/RATING_MAX/RATING_STEP, MOVIES_PAGE_SIZE, DEFAULT_FILTERS), `types.ts` (declares `Movie`/`CastMember`/`FeaturedMovie`/`MovieStatus` — the shared movie vocabulary booking + wishlist import — plus Tab, Filters, MovieQuery, MoviesMeta, CatalogOption, FilterOptions), `utils/url.ts` (searchParams ⇄ state), `api.ts` (`buildMovieQuery`, `getMovies`, `getFeaturedMovies`, `getMovieDetail`, `getGenres`/`getFormats`/`getAgeRatings` — all LIVE), `home.ts` (the home page's streamed feeds — `getHomeFeaturedMovies`/`getHomeNowShowingMovies`/`getHomeComingSoonMovies`, each `cache()`-memoized per request so the four sections reading the now-showing list share one backend call, and each wrapped so a throw returns an `{ error }` union), `detail.ts` (`getMovieRecommendations` — cached per slug+locale so both detail trees share one call), `contexts/` (`MovieListContext` — tab/search/draft-filter state and the feed the provider exposes, while `hooks/useMovieListFeed.ts` owns the page-1 refetch, the stale-response guard and `loadMore` paging; `MovieDetailContext` + `MovieSelectionContext` — the detail payload and the picked showtime; `MoviePreviewContext` — the hover preview shared by the home desktop rows: 200 ms dwell, per-locale detail cache, a slow answer for a movie the cursor already left is dropped).

No mock file.
- `src/hooks/` — `useDevice.ts` (returns `"mobile" | "desktop"` via `matchMedia`), `useMounted.ts` (post-mount flip for staged entry animations), `useAppendReveal.ts` (grow-reveal + scroll for movies/tickets/reviews lists), `useDebouncedValue.ts` (value that settles after `delayMs`)
- `src/libs/utils.ts` has `slugify`, `formatVND`, `formatDate`, `formatRelativeTime`, `toLocaleTag` (the single `en`→`en-US`/`vn`→`vi-VN` mapping every `toLocale*` call needs), `getSafeReturnUrl`, `authReturnTarget`, `buildLoginUrl`, `buildRegisterUrl`; `src/libs/date.ts` has `formatDateOnly` (calendar dates), `CINEMA_TIMEZONE` + `todayInCinemaZone()` (the cinema's day, never the device's — chips and date params are keyed on it); `src/libs/zod.ts` has shared Zod validators (`isValidPhone`, password regex patterns) and `PASSWORD_RULES` (the checklist/schema single source); `src/types/index.ts` holds only `Device` — the movie vocabulary (`Movie`, `CastMember`, `FeaturedMovie`, `MovieStatus`) is declared in `features/movies/types.ts`, so a domain type never lives above the domain that owns it. Feature-specific types live in `features/*/types.ts` (or a `types/` folder once a domain outgrows one file). Feature-specific Zod schemas live in `features/*/schema.ts`.
