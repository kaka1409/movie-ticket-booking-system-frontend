# State management (detail)

## State Management

- `src/contexts/` holds cross-cutting contexts: `DeviceContext.tsx` (server UA-guessed `initialDevice` so first paint skips the mobile→desktop flash), `LocaleContext.tsx`, `AuthContext.tsx`. AuthContext provides `{ user, token, isAuthenticated, isLoading, setAuth, clearAuth, updateUser }` — state only, no API actions. Feature-specific contexts live one per file in `src/features/*/contexts/<Name>Context.tsx` (R4) — never a `context.tsx` barrel.
- **Movies page**: React Context (`src/features/movies/contexts/MovieListContext.tsx`) with URL sync via `router.replace` (initial tab/query/filters seeded server-side, no `useSearchParams`). Draft state: `activeTab`, `query`, `appliedQuery` (300 ms debounce), `filtersOpen`, `filters`, `appliedFilters`; the result list is `hooks/useMovieListFeed.ts` (`movies`, `total`, `hasMore`, `isLoadingMore`, `isFetching`, `fetchError`, `loadMore`, `retryFetch`). URL-synced params: `status`, `q`, `genres`, `ratingMin`, `ratingMax`, `length`, `format`, `ageRating`, `release`. Non-URL state: `filtersOpen` plus the uncommitted `query`/`filters` drafts (committed on the debounce tick / Apply).
- **Tickets listing**: server-side URL pager — `(main)/tickets/page.tsx` reads `?tab=upcoming|past&page=N`, fetches only the visible tab (`getUpcomingTickets`/`getPastTickets`), renders `Tabs` + `Pager` (`components/shared/Pager.tsx`: prev/next + 5 windowed numbers, hidden on a single page). No listing context, no client slicing; desktop `TicketsContent` renders the 2-column ticket-stub card grid (`components/desktop/TicketsContent.tsx`) over the same server data.
- **Booking flow**: central `useReducer` draft — `BookingProvider` (`src/features/booking/contexts/BookingContext.tsx`) wraps all booking steps at `booking/[slug]/layout.tsx` and holds one `BookingState` (cinema slice incl. `cinemaQuery`, seat selection + live `seatGrid`/`maxSeats`, snack arrays, contact, `paymentMethodId` + `paymentMethod`, countdown, `holdExpiresAt` + `holdShowtimeId`) driven by the typed `bookingReducer` in `src/features/booking/stores/reducer.ts` (`BookingState`/`BookingAction` live in `stores/types.ts`, `INITIAL_BOOKING_STATE` in `stores/initial.ts`, the folder barrel is `stores/index.ts`) (`SET_CINEMA`/`SET_CINEMA_QUERY`/`SET_CINEMA_DATE`/`CLEAR_CINEMA_SLOT`/`ADOPT_MOVIE`/`ADOPT_SEAT_GRID`/`SET_SEAT_GRID`/`SELECT_HOLD_CELLS`/`CLEAR_SEAT_SELECTION`/`TOGGLE_SEAT`/`SET_SNACKS`/`SET_CONTACT`/`SET_PAYMENT`/`SET_HOLD`/`START_COUNTDOWN`/`EXPIRE_SESSION`/`RESET`). The context setters (`setCinema`, `setCinemaQuery`, `toggleSeat`, `setSnacks`, `setCredentials`, `setPayment`, `setSeatHold`, `startCountdown`, `expireSession`, …) are thin dispatch wrappers so consumers stay prop-stable. One 10-minute session starts at the first seats-step CTA (`START_COUNTDOWN` no-ops afterwards — re-presses never extend it) and persists across refreshes via `sessionStorage("booking:countdownStart")`; `EXPIRE_SESSION` (fired by `SessionExpiryWatcher`) drops the clock so a re-pick + CTA starts a new session. Derived values (`total`, `ticketCount`, `ticketPrice`, `snackTotal`, `seatType`) are computed in the value memo — never stored in state; `selectedSeats` is derived inside the reducer from `seatGrid`. `resetBooking()` (dispatch `RESET`) runs from `PaidBookingReset`.

  Seat slices follow the showtime they belong to: `SET_CINEMA` with a **different** `showtimeId` (and `SET_CINEMA_DATE`/`CLEAR_CINEMA_SLOT`, which void it) clears `seatGrid`/`selectedSeats`/`maxSeats`, while `holdExpiresAt`/`holdShowtimeId` survive so the old hold can still be released against its own showtime. `ADOPT_SEAT_GRID` carries `restoreHeldSeats` (restore may overrule `occupied` cells when the draft owns a live hold of that same showtime) and `SELECT_HOLD_CELLS` always may, because a server-confirmed hold record is authoritative. Both match on `seatIds`, never on labels.

- **Wishlist**: React Context (`src/features/wishlist/contexts/WishlistContext.tsx`) — `WishlistProvider` at root layout, `useWishlist()` hook. `toggleWishlist(id, feedback?)` is the single choke point for every heart: optimistic local toggle + BE sync when logged in (rollback on real failures) + toast feedback; logged-out picks mirror to `localStorage("wishlist")` and restore on mount (two-pass effect with `eslint-disable`, no hydration mismatch since storage has no server equivalent).
- **Toast**: `ToastContext.tsx` (`ToastProvider` outermost in root layout, `useToast().notify(message, { variant, durationMs? })` — success/error/info, max 3 stacked, 3 s auto-dismiss, click to close) + `components/ui/ToastViewport.tsx` (fixed stack, `aria-live="polite"`). Use for simple notifications; keep dedicated snackbars when an action button is needed (wishlist Undo).
- **Transfer flow**: React Context (`src/features/tickets/contexts/TransferContext.tsx`) for the transfer draft (selected seats, recipient, transfer snacks), and `src/features/tickets/contexts/TicketDetailContext.tsx` for the ticket-level state (ticket, viewerRole, transfer, incomingTransfer). Transfer state is managed in the backend via the ticket's `transfer`/`incomingTransfer` fields; the frontend only displays and decides actions based on that.
  - TransferContext: `selectedSeats`, `recipient`, `transferSnacks` (for the transfer confirmation step)
  - TicketDetailContext: `{ ticket, viewerRole, transfer, incomingTransfer }` from layout
- **Booking step data flow** — no per-step contexts: `src/features/booking/contexts/` holds only the two flow-wide ones (`BookingContext` = the draft, `CountdownContext` = the single 1-second ticker). Server pages fetch catalogs and pass them as props, step state lives in the booking reducer, and components read `useBooking()` plus pure helpers in `features/booking/utils/`:
  - **Cinema step** — `CinemaAdopter` (`components/adopters/CinemaAdopter.tsx`, effect-only, mounted once by the page) adopts the server-resolved URL selection into the draft (URL params win over the saved draft; a URL date that differs clears the stale selection) plus the slim `BookingMovie` snapshot. That snapshot is the step's only `GET /movies/:slug` fetch: credentials/payment read `movie` from `useBooking()` instead of refetching, guarded by `RequireDraft`. Handlers sit where the data is: `CinemaList` toggles slots through `resolveSlotSelection`, `DatePickerWrapper` dispatches `setCinemaDate` + `router.replace`, `SearchBar`/`BottomBar` read and write the draft directly. No mirror effect, so UI and draft cannot diverge.
  - **Seats step** — the grid lives in the reducer as `seatGrid`; `SeatMapAdopter` (`components/adopters/SeatMapAdopter.tsx`, effect-only, mounted **once at page level**) adopts the server map (`ADOPT_SEAT_GRID` re-marks the draft's saved seats by `seatIds`, and may overrule `occupied` cells only when the draft owns a live hold of that same showtime), syncs `?showtimeId=` deep links into the draft and runs the hold lifecycle, while `SeatMapWrapper` only paints `seatGrid ?? restoreSelectedSeats(initialRows, selectedSeats)` so first paint never flashes an empty map. `TOGGLE_SEAT` is one pure transition (sweetbox pair toggle, cap counts CHAIRS via `seatIds.length`, derives `selectedSeats`) and never starts the countdown. Sweetbox cells share one label (`I(1-2)`) for 2 chairs. The hold network side lives in `hooks/useSeatHolds.ts` (restore / release-on-empty / release-orphan-on-slot-change / expiry) and the seats CTA in `hooks/useSeatHoldSubmit.ts` (its `409` recovery refetches with the caller's Bearer token).
  - **Snack step** — the selected `combos[]`/`foods[]` arrays in the draft are the single source of truth (back-navigation restore and zeroing come for free); steppers upsert through `withItemQty()` → `setSnacks`. No qty records, no sync effects.
  - **Status pages** — no context: each `page.tsx` derives `transactionId`/`reason` server-side (URL param → fetched-booking fallback) and passes `movie`/`booking`/`reason`/`transactionId` as props; entry animations use the shared `useMounted()` hook (`src/hooks/useMounted.ts`); `PaidBookingReset` (effect-only) dispatches `resetBooking()` once the fetched booking is `paid`.
- **Other pages**: Local `useState` or no state needed.
